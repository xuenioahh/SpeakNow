# SpeakNow spatial studio implementation

Implemented in the existing Omniverse working tree, October 8, 2026. Browser acceptance is still pending; this document distinguishes implemented behavior from verified behavior.

## Existing engineering and design

React 18 / Vite 6; Three.js 0.171; Framer Motion 11; Recharts 2. No dependency was added. The existing violet/indigo primary, warm accent, dark neutral surfaces, and contextual sage scene/profile palette remain. The visual system adds quiet ambient lighting, three surface depths, fine edge reflections, short transitions, and a central interactive presence.

The existing routes, authentication, localApi requests, entity storage, database schema, report calculations, and video-expression evidence remain. The project already had uncommitted changes. A pre-upgrade source snapshot was saved at `/tmp/speaknow-spatial-before/src` to distinguish this work from those changes.

## Phase 1 — audit

Read App routing, global styles, Home/VoiceSetup/VoiceChat, voice components, VoiceReport/VoiceHistory, presentation practice/feedback/report/history, Profile/analytics, audioManager, localClient, localStore, and scene rendering. Baseline build and lint passed. The original typecheck has 36 diagnostics.

The microphone uses browser SpeechRecognition. AI replay uses browser SpeechSynthesis. Voice reports are generated by the existing local report function; conversation replies use the existing API. None of these evaluation or persistence paths was replaced.

## Phase 2 — voice presence and audio

- `src/components/spatial/VoiceOrb.jsx`: actual Three.js sphere geometry, a bounded flowing vertex shader, layered transparent shell, sphere lighting, interior color variation and rim highlight. Idle, listening, processing, speaking, completed and error states come from real application state. Completion is a single restrained highlight.
- `src/lib/audioEnergy.js`: Web Audio RMS energy from the microphone stream, smoothed attack/release and a 0–1 limit. The microphone is never connected to speaker output.
- `src/components/voice/RecordingControls.jsx`: preserve transcription, silence sending, typed replies and retries; own/release the metering stream and audio context; detach callbacks; cancel delayed restarts; release permission results received after cancellation; react to device disconnection. Explicit exit/end stops input before the route animation.
- `src/lib/audioManager.js`: report speaking only from actual utterance start/end; preserve replay identity across chunks; prevent cancelled playback events from clearing a newer playback.

Important limit: SpeechSynthesis does not provide a PCM/media stream to this application. Speaking changes the orb's visual state when audio actually starts, but its amplitude is not fabricated. Actual AI output-energy deformation requires an analyzable audio source that the current API does not provide. No audio API, database field or provider was added to pretend otherwise.

Validation: executable RMS, smoothing, cap, silence, Safari constructor, disposal and speech lifecycle tests pass (`scripts/check-spatial-audio.mjs`). These use controlled browser API fixtures; they are not a physical microphone/browser acceptance test.

## Phase 5 — reports and growth

- `components/report/RadarChart.jsx`: original numerical scale and coordinate system, subtle projection beneath the data, gradient depth, 550ms expansion, hover tooltip, keyboard-selectable dimensions with exact scores and up to five comparable saved measurements. Invalid/missing/out-of-scale/fallback measurements are excluded from dimension history.
- `components/report/PracticeTimeline.jsx`: actual dated sessions only, newest emphasis, natural hovering and explicit dates/durations. Each entry expands the real saved record or links to its history with the existing session ID.
- `Profile.jsx`: uses original scoring groups and analytics; radar supplements the existing precise progress bars; separate score scales remain separate. Original trend chart/table remain.
- `VoiceHistory.jsx` / `PresentationHistory.jsx`: accept `?session=...` to expand the actual record; retain deletion, report detail and replay functionality.

Actual React server rendering checks passed for score labels, chronological timeline, invalid-date exclusion and links. This validates rendering/data wiring, not browser layout.

## Phase 6 — motion, performance and acceptance

- `App.jsx`: short exit/enter transition, user reduced-motion preference, lazy page imports; existing routes unchanged.
- Orb loaded only for speaking practice; existing environment preview remains lazy. Production build emits separate VoiceChat, VoiceOrb, Profile and Three.js chunks.
- Orb DPR capped at 1.5 desktop / 1.25 mobile; mobile geometry and antialiasing reduced; mobile animation limited to approximately 30fps. No particles or postprocessing.
- Pause offscreen, hidden or unfocused; dispose renderer, geometry, materials, observers, listeners and audio resources on teardown.
- Reduced motion: static 3D render with state updates, no looping movement; global transitions reduced.
- WebGL creation failure/context loss: styled 2D orb with intact input and session controls. Error state stays steady.
- Canvas ignores pointer input. Buttons, dimensions, summaries and controls retain keyboard focus and readable labels.

### Browser verification limitation

Attempted to start Vite on `127.0.0.1:5173`: the managed environment rejects listening with `EPERM`. Attempted Playwright with installed desktop Chrome: the browser process aborts under the managed environment (`SIGABRT`; process control also reports `EPERM`). WebKit's Playwright executable is not installed. No browser screenshot, Safari result, real-device result or passing browser run is claimed.

`scripts/check-spatial-browser.cjs` contains a reproducible interaction suite. It intercepts API writes and uses an oscillator-fed test microphone and controllable speech events. It covers queue/start/end truthfulness, recording/cleanup/denied permissions, request/processing/completion, report save/retry, saved-record navigation, radar dimensions, existing scenario entry, 390px/320px layouts, reduced motion, WebGL loss and no-WebGL input. Its syntax check passes; execution is blocked at browser launch before assertions run. Existing `scripts/check-immersive-browser.cjs` remains available for all twelve environment previews.

On a machine with local browser/server permission:

```sh
npm run dev
# In another terminal, with Playwright installed or PLAYWRIGHT_MODULE set:
CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' node scripts/check-spatial-browser.cjs
node scripts/check-immersive-browser.cjs
# With Playwright WebKit installed (do not set CHROME_PATH):
SPEAKNOW_BROWSER=webkit node scripts/check-spatial-browser.cjs
```

Before treating this as launch-approved, run those browser suites, inspect screenshots and manually verify physical microphone/SpeechRecognition, Safari/iOS voice playback, keyboard focus, desktop/mobile layouts, low-performance rendering, and actual backend report save/reload. Mobile viewport assertions are not physical-device testing.
