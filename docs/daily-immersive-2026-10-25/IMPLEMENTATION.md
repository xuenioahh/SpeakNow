# Daily Speaking immersive conversation — implementation record

## Flow

`/voice/prepare?scenario=cafe` shows guidance over the live Three.js room. Selecting a conversation moves the existing camera. Start Conversation sets `stage=conversation` on the same route, preserving the Canvas, models and lighting. `/voice/chat` remains a direct entry for saved retries. Finish saves the attempt before navigating to `/practice/review`.

On narrow viewports, subtitles default to the bottom of the scene so the Live Performance overlay does not cover the NPC or subtitle text.

## Data and measurement

| Metric | Trigger and source | Status |
|---|---|---|
| Volume | Microphone RMS samples, dBFS | Implemented |
| Pauses | Microphone voice activity threshold and silence window | Estimated |
| Speech continuity | Voiced time / elapsed speaking time | Proxy; not a fluency score |
| Pace | Confirmed words / voiced seconds | Estimated when enough speech is available |
| Filler words | Confirmed transcript matches `um`, `uh`, `erm` | Transcript only |
| Head orientation and camera direction | MediaPipe face landmarks, nose relative to eyes | Orientation proxies; not eye contact |
| Framing | Observed face center in camera frame | Implemented when landmarks exist |
| Visible posture | MediaPipe visible shoulder alignment | Partial body only |
| Hand movement | Changes in visible wrist landmarks | Movement events, not gesture quality |
| Relevance, grammar, vocabulary | Separate DeepSeek text review after each completed learner turn | AI text observations; blank when unsupported or request fails |
| Pronunciation, intonation, speech clarity, gesture types/timing, facial expression, coherence, interaction | No reliable dedicated analysis | Not assessed |

Each measured entry stores its source, latest timestamp, interval, sample count and reliability. Audio samples are gathered only during microphone capture, video observations at up to 4 fps in a Worker, and text analysis once per completed turn. Camera shutdown clears live camera metrics and stops tracks. No visual metric is inferred from transcript, and no pronunciation metric is inferred from recognition quality.

Streaming DeepSeek replies use current scene, task, role and recent dialogue history. The browser plays the actual returned reply through speech synthesis. If streaming or per-turn analysis fails, the user's reply remains available for retry; no fake AI result is shown. The local development server now forwards SSE writes and flushes headers.

Camera preview, on-device landmark analysis, and local audio-video clip buffering have separate opt-ins. A recorded 5–10 second clip is selected only when real media overlaps a recorded learner answer and adequate visual samples. Saved clip metadata includes absolute session interval, related transcript, observations and measurement evidence. Clips remain in local IndexedDB; daily video and visual metrics are excluded from cloud attempt sync and from transcript-only feedback requests.
