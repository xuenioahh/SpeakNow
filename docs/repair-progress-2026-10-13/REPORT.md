## 本轮修复

1. **录音重复／并发上传。** 本地文件先完整写入临时文件，再以不可覆盖的原子操作发布。同一录音 ID 的并发请求核对实际字节；记录追加在锁内去重，容量已满时仍允许已有录音的相同重试。异内容保持拒绝。
2. **录音已上传、记录尚未保存时无法恢复。** 旧实现会因文件已存在返回 500，或在记录更新失败后删除另一个请求已经使用的文件。现在保留已上传对象，相同内容重试可完成记录关联；不同内容返回 409。未关联对象的自动清理尚未实现。
3. **MediaRecorder 启动异常卡住退出／保存。** 启动抛错现在会结算本次等待；每个录音器持有自己的完成回调，失败录音不提交残缺音频。浏览器实测失败后可退出、恢复文字并完成新的录音保存。
4. **管理日志绕过隔离目录、损坏清空和并发丢失。** 管理日志改用共享原子存储及 `SPEAKNOW_DATA_DIR`，损坏数据明确报错并保留原字节。Serverless 缺少持久目录时不再静默使用 `/tmp`。
5. **管理云端失败被伪装成本地成功。** 读取、写入、删除失败统一返回 503；删除云端失败后的本地回退。用户记录使用受检查的 upsert，避免吞掉 PATCH 失败。接口保留 403／503 等真实状态。
6. **管理事件中的会话内容可由客户端伪造。** 保存会话事件现在从当前用户的服务端记录读取会话，拒绝跨用户 ID；SQL 补上管理表 RLS 与匿名／普通用户权限撤销。迁移文件已准备，未对线上数据库执行。
7. **旧回归脚本失效。** 空间测试补齐识别启动确认，使用当前请求完成状态，区分 ActivityRecord 与 VoiceSession，验证新报告没有虚构分数；传输取消测试补齐 CSRF 浏览器环境。报告展示检查改为当前证据契约；性能检查验证当前组件，历史对比缺失时明确标记未验证。新增统一 `npm test` 入口。

主要改动：`api/_mediaStore.js`、`presentation-media.js`、`_appStore.js`、`_adminDb.js`、`_adminStore.js`、`admin-track.js`、`src/impact/PresentationCapture.jsx`、相关回归脚本及 SQL。
