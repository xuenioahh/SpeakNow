# 第一轮逐场景精修：Brew & Bean 咖啡馆

日期：2026-10-11。此次先完成咖啡馆的 3D 场景与对话衔接，其余场景维持原有体验。

## 用户现在可以做什么

1. 在真实练习页打开咖啡馆，选择菜单、咖啡杯或糕点。
2. 查看情境提示，点击 **Use as a reply draft**，将建议放入原有回复框。
3. 修改后再发送，或用原有录音功能表达。选择物件和使用草稿不会自动发送、下单或改变评分。
4. 场景旁显示咖啡师最新回复，**Reply to the barista** 返回原有回复框。发送、录音和等待响应时，草稿操作会锁定；已有未发送文字不会被替换。
5. 请求失败后仍可重试。重试沿用原回合的物件上下文，即使后来探索了另一个物件。
6. 语法等 Coach note 默认折叠，可主动展开；对话本身先保持自然。

自由聊天使用咖啡推荐、口味与糕点等开场，不把五人订单塞进自由聊天。

## 3D 与布局

- 咖啡师增加围裙细节，并根据真实 listening/speaking 状态作轻微转身或点头；不模拟口型或随机音量。降低动态效果时不持续点头。
- 场景打开时解除原聊天容器的高度裁切，画面、物件列表和提示完整纳入页面滚动。
- 手机上缩小旁侧 Voice Orb 的占用；保留同一个真实状态组件和录音控件。
- 探索时新消息不再强制滚动到聊天底部。关闭场景恢复原对话布局。
- WebGL 不可用时，物件按钮与草稿衔接仍然可用。

## AI 对话

咖啡馆接口接收受限的物件 ID，并从固定说明中选择情境。订单任务要求只追问一个缺失细节，保留已提到的饮品、数量、奶类、外带和糕点要求，处理修改，并在用户准备好时复述已明确的信息。

咖啡馆上下文从原来的两条消息扩展到最多二十条有效近期消息，每条最多 1200 字符；当前用户回合单独发送一次。没有新增订单数据库或把物件浏览当成完成进度。

菜单没有给出的价格、库存、糕点成分不得编造。文字回复不能被当成发音证据。在线不可用时提供明确标注的 **Local practice prompt**，不伪装成确认订单的在线咖啡师。

## 验证与边界

- `scripts/check-cafe-dialogue.mjs`：订单历史、修改饮品、上下文边界、自由聊天区别、诚实的本地练习。
- `scripts/check-cafe-browser.cjs`：真实页面草稿衔接、已有文字保护、等待锁定、失败重试上下文、回复同步、Coach note、场景开关、320/390/768px 布局、机场隔离、无 WebGL。
- `scripts/check-voice-interaction.mjs`：原有录音和对话生命周期回归。
- TypeScript、ESLint、生产构建均通过。
- 十二场景、三十六物件提示及 320–1920px 完整回归通过，含触屏、键盘、降低动态效果、WebGL 丢失与重试、无 WebGL 降级。

浏览器使用隔离身份和受控接口响应；真实付费模型是否始终遵循新 prompt、真实麦克风和浏览器语音播放的最终体验，尚未实测。近期消息超过二十条后，较早订单细节仍可能离开上下文；此次未实现永久订单记忆。
